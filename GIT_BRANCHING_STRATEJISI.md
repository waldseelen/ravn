# Git Branching Stratejisi\n\n## Branching Model: Git Flow\n\nRAVN projesi Git Flow branching modelini kullanır. Bu model, feature geliştirme, release ve hotfix'leri sistematik şekilde yönetir.\n\n### Branch Türleri\n\n#### 1. **main** (Üretim Branch'i)\n- **Amaç:** Her zaman stabil, release-ready kod içerir\n- **Kural:** \n  - Doğrudan commit yapılmaz\n  - Yalnızca PR aracılığıyla (Code Review sonrası) merge edilir\n  - Her merge bir production release olarak kabul edilir\n- **Etiket:** `v1.0.0`, `v1.1.0` vb. semantic versioning ile etiketlenir\n\n```bash\ngit checkout main\ngit pull origin main\n```\n\n#### 2. **develop** (Geliştirme Branch'i)\n- **Amaç:** Sonraki release'in test ve entegrasyon branch'i\n- **Kural:**\n  - Tüm feature branch'leri buradan dallanır\n  - Her zaman test edilmiş, çalışan kod içermeli\n  - Release öncesi staging ortamında test edilir\n\n```bash\ngit checkout develop\ngit pull origin develop\n```\n\n#### 3. **feature/*** (Özellik Branch'leri)\n- **Adlandırma:** `feature/video-converter`, `feature/codec-checker`\n- **Kaynak:** `develop` branch'inden\n- **Hedef:** `develop` branch'ine PR ile merge\n- **Yaşam süresi:** Feature tamamlanıncaya kadar\n\n```bash\n# Yeni feature başlat\ngit checkout -b feature/my-feature develop\n# Kod yaz ve commit yap\ngit push origin feature/my-feature\n# GitHub'da PR açarak develop'a merge et\n```\n\n#### 4. **bugfix/*** (Bug Düzeltme Branch'leri)\n- **Adlandırma:** `bugfix/download-error`, `bugfix/ui-crash`\n- **Kaynak:** `develop` branch'inden\n- **Hedef:** `develop` branch'ine PR ile merge\n\n```bash\ngit checkout -b bugfix/critical-bug develop\n```\n\n#### 5. **release/*** (Release Hazırlık Branch'leri)\n- **Adlandırma:** `release/v1.1.0`\n- **Kaynak:** `develop` branch'inden\n- **Hedef:** Hem `main` hem `develop` branch'lerine merge\n- **Kullanım:** Release test ve minör bug fix'leri\n\n```bash\n# Release branch oluştur\ngit checkout -b release/v1.1.0 develop\n# Version numarasını güncelleyip commit yap\ngit push origin release/v1.1.0\n# GitHub'da PR açarak main'e merge et\n```\n\n#### 6. **hotfix/*** (Acil Düzeltme Branch'leri)\n- **Adlandırma:** `hotfix/critical-security-fix`\n- **Kaynak:** `main` branch'inden\n- **Hedef:** Hem `main` hem `develop` branch'lerine merge\n- **Kullanım:** Üretim ortamında keşfedilen kritik hataları düzelt\n\n```bash\n# Acil düzeltme branch'i\ngit checkout -b hotfix/security-patch main\n# Düzeltmeyi yap\ngit push origin hotfix/security-patch\n# PR ile hem main hem develop'a merge et\n```\n\n---\n\n## Workflow Örnekleri\n\n### Yeni Feature Geliştirme\n\n```bash\n# 1. develop'dan yeni branch oluştur\ngit checkout develop\ngit pull origin develop\ngit checkout -b feature/video-trimmer\n\n# 2. Kod yaz ve commit yap\n# ...\ngit add .\ngit commit -m \"feat: Add video trimming functionality\"\ngit push origin feature/video-trimmer\n\n# 3. GitHub'da Pull Request aç\n# - Base: develop\n# - Head: feature/video-trimmer\n# - Title: \"Add video trimmer module\"\n# - Description: \"Fixes #123 - Implements basic video trimming\"\n\n# 4. Code review ve approval sonrası merge\n# (\"Squash and merge\" seçeneği önerilir)\n```\n\n### Bug Düzeltme\n\n```bash\n# develop'da bug bul\ngit checkout develop\ngit pull origin develop\ngit checkout -b bugfix/encoding-error\n\n# Düzeltmeyi yap\ngit add .\ngit commit -m \"fix: Resolve FFmpeg encoding error for VP9\"\ngit push origin bugfix/encoding-error\n\n# PR ile develop'a merge\n```\n\n### Release Hazırlama\n\n```bash\n# Release branch oluştur\ngit checkout -b release/v1.1.0 develop\n\n# Version'u güncelle\n# ravn_app/__init__.py: __version__ = \"1.1.0\"\n# CHANGELOG.md: Güncellemeler ekle\n\ngit add .\ngit commit -m \"chore: Prepare v1.1.0 release\"\ngit push origin release/v1.1.0\n\n# PR ile main'e merge\n# Tag oluştur: git tag -a v1.1.0 -m \"Version 1.1.0\"\n# PR ile develop'a da merge\n```\n\n### Acil Üretim Düzeltmesi\n\n```bash\n# main'den hotfix branch oluştur\ngit checkout main\ngit pull origin main\ngit checkout -b hotfix/security-patch\n\n# Düzeltmeyi yap\ngit add .\ngit commit -m \"hotfix: Security patch for dependency vulnerability\"\ngit push origin hotfix/security-patch\n\n# PR ile main'e merge ve tag oluştur\n# PR ile develop'a da merge\n```\n\n---\n\n## Commit Mesajı Konvensiyonu\n\nProje [Conventional Commits](https://www.conventionalcommits.org/) standardını kullanır.\n\n### Format\n```\n<type>(<scope>): <subject>\n\n<body>\n\n<footer>\n```\n\n### Tip Örnekleri\n- **feat:** Yeni özellik\n- **fix:** Bug düzeltme\n- **docs:** Dokümantasyon\n- **style:** Kod stili (formatting)\n- **refactor:** Kod yeniden yapılandırma\n- **perf:** Performans iyileştirmesi\n- **test:** Test ekleme/güncelleme\n- **chore:** Build, dependencies vb.\n\n### Örnekler\n\n```\nfeat(downloader): Add video quality selection\n\nImplement quality dropdown menu with 4 options:\n- En İyi (best)\n- 1080p\n- 720p\n- 480p\n\nFixes #45\n```\n\n```\nfix(ui): Fix theme not applying on startup\n\nTheme was not being applied because apply_theme()\nwas called before bg_label was fully initialized.\n\nFixes #78\n```\n\n---\n\n## Pull Request (PR) Süreci\n\n### PR Açarken\n1. **Branch'i güncelleyin:** `git pull origin [base-branch]`\n2. **Conflict çözün** (varsa)\n3. **PR açınız:** GitHub'da \"New Pull Request\" butonu\n4. **Başlık:** Clear, concise (ör: \"Add video converter UI\")\n5. **Açıklama:** Neyi yaptığınızı, neden yaptığınızı açıklayın\n6. **Linked Issues:** İlgili issue'yu referans verin (`Fixes #123`)\n\n### PR Şablonu (PULL_REQUEST_TEMPLATE.md)\n\n```markdown\n## Açıklama\nBu PR'ın amacını açıkla.\n\n## Değişiklikler\n- [ ] Feature A eklendi\n- [ ] Bug B düzeltildi\n\n## Test Edildi\n- [ ] Birim testleri\n- [ ] Manual testler\n\n## Checklist\n- [ ] Kod review edildi\n- [ ] Testler geçti\n- [ ] Dokümantasyon güncellendi\n\nFixes #123\n```\n\n### PR Review Kriterleri\n1. **Kod Kalitesi:** Bakılabilir, verimli\n2. **Testler:** Tüm testler geçiyor mu?\n3. **Dokümantasyon:** Kod yorum ve docstring var mı?\n4. **Performans:** Kritik performance problemleri var mı?\n5. **Güvenlik:** Güvenlik açığı var mı?\n\n---\n\n## CI/CD Pipeline\n\nHer push/PR'da otomatik olarak:\n1. **Linting:** Code style kontrol\n2. **Testler:** Unit ve integration testleri çalıştırma\n3. **Coverage:** Test kapsamı raporu\n4. **Build:** Windows EXE oluşturma (main branch'i için)\n\nBakınız: `.github/workflows/tests.yml`\n\n---\n\n## Versioning\n\nProje [Semantic Versioning](https://semver.org/) kullanır: `MAJOR.MINOR.PATCH`\n\n- **MAJOR:** Incompatible API changes\n- **MINOR:** New features (backwards compatible)\n- **PATCH:** Bug fixes\n\nÖrnek: `1.2.3`\n- 1 = MAJOR\n- 2 = MINOR\n- 3 = PATCH\n\n---\n\n## Sıkça Sorulan Sorular\n\n**S: Feature'ımı hangi branch'tan başlatmalıyım?**\nA: Daima `develop`'dan. `feature/[name]` şeklinde yeni branch oluşturun.\n\n**S: Ana branch'e (main) doğrudan push yapabilir miyim?**\nA: Hayır. `main` branch'i korunduğu için sadece PR aracılığıyla merge edilebilir.\n\n**S: Feature'ımı ne zaman tamamlı olarak görebilirim?**\nA: PR merge edildikten ve develop'dan main'e promote edildikten sonra.\n\n**S: Conflict çözmek gerekirse ne yapmalıyım?**\nA: Lokal'de `git merge develop` yap, conflict'leri çöz, push et.\n\n---\n\n**Sonsonuç:** Bu branching stratejisi, takım işbirliğini, kod kalitesini ve release yönetimini sistematik hale getirir.\n"
