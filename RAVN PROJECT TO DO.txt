# Handoff: Migrate RAVN GUI from Tkinter to Tauri

## Project Goal

The goal is **not** to rewrite the application.

The goal is to replace the current **Tkinter desktop UI** with a modern **Tauri-based frontend**, while preserving the existing Python backend and business logic.

The Python codebase should remain the single source of truth.

---

# High-Level Architecture

Current:

```text
Tkinter
    │
Python Application
    │
Download / Metadata / Library / FFmpeg / yt-dlp
```

Target:

```text
Tauri (Frontend)
        │
 IPC / Local API
        │
Python Backend
        │
Core Business Logic
        │
yt-dlp / FFmpeg / Database / Filesystem
```

The backend should not know whether requests come from:

* CLI
* Tauri Desktop
* future Web UI
* automated scripts

Everything should use the same Python core.

---

# Migration Principles

## DO NOT rewrite business logic.

Keep:

* download engine
* metadata processing
* queue management
* library management
* filesystem operations
* configuration
* ffmpeg integration
* yt-dlp integration

Only replace the presentation layer.

---

## Separate responsibilities

Python should become:

```
backend/
    core/
    services/
    models/
    api/
```

Frontend should become:

```
frontend/
    src/
        components/
        pages/
        stores/
        services/
```

# Backend Requirements

The backend should expose a clean interface.

Avoid GUI-specific code.

Instead of:

```
Tkinter Button
        ↓
Business Logic
```

Use:

```
Frontend Event
        ↓
Backend API
        ↓
Business Logic
```

The business layer should never depend on UI code.

---

# Communication

The frontend should communicate with Python through a clean abstraction.

Possible implementations:

* subprocess
* local HTTP API
* IPC

Choose whichever best fits the existing architecture.

The communication layer should be isolated.

# Migration Strategy

Do not perform a big-bang rewrite.

Instead:

Phase 1

* isolate backend
* remove GUI dependencies

Phase 2

* create Tauri shell

Phase 3

* connect backend

Phase 4

* migrate pages one by one

Phase 5

* remove Tkinter

This minimizes regressions.

---

# Expectations for the AI Agent

Before writing code:

1. Understand the current architecture.
2. Identify business logic mixed with Tkinter.
3. Propose extraction/refactoring where necessary.
4. Preserve behavior.
5. Avoid unnecessary rewrites.
6. Keep commits small and reviewable.
7. Prefer incremental migration over replacing large parts of the codebase.

The objective is to modernize the desktop application while keeping the existing Python engine stable, reusable, and maintainable.
